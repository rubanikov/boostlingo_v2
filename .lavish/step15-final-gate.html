Two real design corrections mid-build

Both caught before shipping, both documented in AGENTS.md, neither silently patched over.

Deepgram's detect_language doesn't support streaming

The approved wayfinder design (ticket 06) assumed it would. Deepgram's own docs say plainly it's pre-recorded-audio-only. Verified replacement: Nova-3's language=multi mode, which tags each word with its own language directly in the streaming results.

OpenAI Realtime session payload was beta-shaped

Ticket 1's original session config used the flat, pre-GA shape. Ticket 3's build verified the current shape against the pinned SDK's own generated types: nested under session.audio.{input,output}, corrected before it shipped.

Validation, fix round, and polish (Steps 11-14)

Step 11 — acceptance verification: all 8 functional requirements traced to real code

Every FR from the brief was traced to actual implementation, not just a ticket's claim. Audio round-trips and real latency/quality numbers are honestly marked as unverifiable without live provider keys, since none exist in this build environment, but the plumbing for all of it is real and tested.

Step 12 — implementation-validator + security-auditor: no Critical findings

Implementation-validator: circuit breaker trips at exactly 5 failures (tested), speaker→voice wraparound handled correctly, no undisclosed scope creep. Two Important findings: malformed WS frames from Deepgram/ElevenLabs could silently hang a session; a malformed 2xx OpenAI response raised an unguarded KeyError.

Security-auditor: no leaked secrets, no XSS, API-key handling solid. One real gap: the /ws/cascade WebSocket had no Origin check, so any webpage open in the same browser could open a session against real API keys with no mic permission needed. A second: the Cascade languages field wasn't validated the way Realtime's already was.

Step 13 — fix round: all four Important findings closed
  • WebSocket Origin validation added, rejecting disallowed origins before .accept()
  • Cascade languages now validated against the same allow-list Realtime already used
  • json.JSONDecodeError now caught in both providers' receive loops, converted to the existing retry/circuit-breaker path instead of hanging
  • Malformed 2xx OpenAI responses now return a clean 502 instead of crashing

All four shipped with regression tests confirmed red before the fix, green after. 86 backend tests passing.
