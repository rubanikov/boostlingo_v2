Framework Choice

Python + TypeScript is decided. Three picks left: backend web framework, frontend framework, and package manager/build tooling — needs to support concurrent WebSocket streaming to multiple providers, fast iteration within the 15–20hr budget, and clean transport/UI separation.

question 1 of 3

Backend: FastAPI or Flask?

FastAPI recommended

Async-native (built on Starlette), first-class WebSocket support (@app.websocket), and the whole architecture in ticket 05 is fundamentally an async-concurrency problem — continuous audio streaming, concurrent calls to Deepgram/OpenAI/ElevenLabs, an async LLM clause-check running alongside all of it. FastAPI fits that shape directly.

Flask

WSGI/sync by default — needs an extension (Flask-SocketIO) or a switch to Quart to get real async WebSocket handling. That's extra plumbing to fight the framework's grain for zero benefit, given the async shape is required either way.

question 2 of 3

Frontend: React, Vue, Svelte, or vanilla+Vite?

This one's genuinely closer to a toss-up architecturally — your own familiarity matters more here than any technical edge, since it's velocity within a fixed 15–20hr budget that's on the line.

React default pick

Largest ecosystem of WebSocket/audio-hook examples to draw from quickly, most broadly recognizable choice for an evaluator skimming the submission. More boilerplate than Svelte for the many small reactive state slices this UI needs (connection status, dual transcripts, latency numbers, mode toggle).

Svelte

Arguably the best technical fit — lightweight reactivity with no virtual-DOM diffing overhead, which suits a UI dominated by high-frequency streaming updates (live transcript tokens, latency numbers). Smaller ecosystem of real-time examples to crib from.

Vue

Middle ground — gentler reactivity model than React, decent ecosystem, less community precedent specifically for real-time audio/WebSocket UIs than React.

Vanilla + Vite

Zero framework overhead, but you'd hand-roll reactive state bindings for a genuinely multi-panel UI — likely more code to get right within the time budget, not less.

Real question for you: how familiar are you with each of these already? Whichever you can move fastest in in a live-coding-adjacent, time-boxed build is probably the right answer regardless of the technical nuances above.
question 3 of 3

Package manager / build tooling

Python: uv recommended

Fast, unified venv + dependency + lockfile tool, current default recommendation for new Python projects — noticeably quicker than Poetry for install/sync in a time-boxed build.

TS: Vite + npm recommended

Vite is the near-universal default dev server/bundler for a React/Vue/Svelte SPA now. Plain npm needs zero extra install step versus pnpm's marginal speed/disk edge — not worth the extra setup for a short-lived project.
