Remaining findings (none critical)

Security — Important (documented in AGENTS.md, not fixed)

  • I1 update_tuning connection-level spam → unbounded Deepgram connect churn (no per-session reconnect rate limit; no-Origin clients admitted by design)
  • I2 audio_queue unbounded + synchronous denoise process() on the event loop (noisereduce ~2.7 s/clip; DFN init ~2.7 s)
  • I3 POST /api/tuning/transcript-check unauthenticated/unmetered LLM proxy (CORS blocks web pages; local processes can hit it)
  • Minor: unbounded requestId/rejected-value logging; json.loads non-JSONDecodeError ValueError; client.* ranges + NaN/Infinity accepted server-side; prompt-injection steerability of corrected; harness path traversal (operator-supplied); DFN weights fetched unpinned

Review — Important / design

  • Provider-boundary leak: orchestrator builds DeepgramParams; params: Any on the STT Protocol
  • Three range tables (fingerprint / orchestrator / realtime) + panel step literals; TS/Py canonicaliser latent divergences (null handling, post-step re-clamp) not exercised by the fixture; schema.py comment still says step 0.05; ttsVoiceA default "" server-side
  • TuningPanel.tsx ~1600 lines / 19 mode switches; stringly knob paths; duplicated §7 renderers; report script hardcodes captures path (per-config --out can't be read back)
  • Reconnect applies untimed across an unexpected drop→resume; Cascade DSP ctx is 48 kHz only with RNNoise (AGENTS.md says "always")
  • Apply-during-silence leaves the badge amber until speech (by design; copy doesn't say so)
