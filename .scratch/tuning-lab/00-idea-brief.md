# Idea brief — Audio Tuning & Denoise Lab

Approved at feature-factory Step 0b (2026-08-15). Lavish artifact: `.lavish/step0-idea-brief-tuning-lab.html`.

## Rough request (verbatim)
"add some denoise options and also include all tuning option in the app, for example, rms threshold, and any other used" — later: "the three plus RNNoise, Demucs / Wave-U-Net and any other you consider useful, the idea is to check if those can improve the Word Error Rate and other metrics. also as a third, the llm that we are using for cascade, does it check if it is valid. Also what about an llm that checks if the text sounds correct" — and at the gate: "I want the noise attenuation and the other parameters as part of user selection in the tuning panel" / "i want all the processing steps like denoise in the tuning panel."

## Destination
Every audio / turn-taking / segmentation / denoise / transcript-check knob (and curated model pickers) is a user selection in an in-app Tuning panel, applied at session start and live mid-session, AND every configuration is measurable: a noisy-corpus benchmark reports WER, LLM-judge score and added latency per config fingerprint.

## Locked decisions
1. **Denoise scope**: browser constraint toggles (EC/NS/AGC) + OpenAI Realtime `input_audio_noise_reduction` (off/near_field/far_field) + NEW client-side RMS noise gate (threshold dBFS, hold ms, attack/release ms, attenuation dB from soft duck to full mute) + RNNoise-WASM (client) + DeepFilterNet (server, Cascade; attenuation limit dB, post-filter strength) + noisereduce (server, Cascade; prop_decrease, stationary/non-stationary) + offline-only Demucs/denoiser (DNS). Wave-U-Net only if a maintained package exists, else dropped without a new gate. Goal: check whether WER and other metrics improve. PLUS a NEW LLM "transcript check" stage.
2. **Split by latency class**: live path = browser NS, RMS gate, RNNoise, OpenAI near/far, DeepFilterNet, noisereduce. Offline benchmark only = Demucs/denoiser (+ every live option).
3. **Exposure**: in-app Tuning panel per mode; values sent at session start (Realtime `POST /api/realtime/session` body; Cascade WS `start_session`) AND applied live mid-session (Realtime `session.update` over the `oai-events` data channel; Cascade via new WS control messages, with a deliberate Deepgram reconnect where params are connection-level). localStorage persistence. `.env` becomes server defaults, not the only source.
4. **Transcript check LLM**: per-session mode `off / flag / correct`. Cascade: all three; Realtime: off/flag only (no seam to correct). `correct` rewrites the source transcript before translation and gets its own latency stage; benchmark reports raw vs corrected WER. `flag` is non-blocking and annotates the segment as suspicious.
5. **Knob inventory** — Client (both modes): EC/NS/AGC toggles; RMS gate (+params); RNNoise. Realtime: turn detection `server_vad`/`semantic_vad`; `threshold`, `prefix_padding_ms`, `silence_duration_ms`, `interrupt_response`, semantic `eagerness`; `input_audio_noise_reduction`; transcript check off/flag; model picker; voice picker. Cascade: Deepgram `endpointing`, `utterance_end_ms`, diarize on/off, Deepgram model picker; segmentation mode hybrid-race/llm-priority + segmentation model picker; server denoise (off/DeepFilterNet/noisereduce + params); transcript check off/flag/correct; translation model picker; TTS voice picker. Model pickers are curated allow-lists validated server-side (never free text).
6. **Benchmark**: synthesize noisy variants of the existing 33-item corpus — babble built from several overlaid TTS speakers (same + other language), street, fan/white — at ~20/10/5 dB SNR; PLUS a small user-supplied real recording set (harness self-skips when absent, like `run_real_audio_report.py`). Run every config through (a) a backend-only Cascade STT harness (extend `stt_replay.py`) and (b) the fake-mic Playwright harness (`realtime-quality-capture.mjs`). Report WER, LLM-judge score, added latency per config fingerprint; clean baseline always shown; new COMPARISON.md section.
7. **Priority (cut from the bottom)**: (1) Tuning panel + TuningConfig plumbing for existing knobs, live apply → (2) noisy corpus + benchmark harnesses → (3) RMS gate, RNNoise, OpenAI near/far → (4) transcript check → (5) DeepFilterNet + noisereduce + offline denoisers → (6) model pickers.
8. **Heavy ML deps**: torch-based denoisers behind an optional extras group (`backend[denoise]`) + runtime detection (capability discovery); panel shows uninstalled stages disabled with a "not installed" hint; CPU-only; core CI stays torch-free.
9. **Presets & comparability**: one shared `TuningConfig` JSON schema across UI, backend, and harness; built-in presets (e.g. "Provider defaults", "Tuned turn-taking", "Max denoise") + user-saved presets in localStorage; JSON export/import; a short fingerprint hash of the config stamped on latency records and every quality report row.
10. **Non-goals**: no server-side/account preset storage; no GPU requirement; no Demucs/Wave-U-Net in the live path; no `correct` mode in Realtime; no per-device mic calibration wizard; no new language pairs (EN↔ES/FR stays); real noisy recordings supplied by the user.
11. **Every processing step is a user selection in the Tuning panel with its parameters** — each denoise stage is its own toggle with its own parameters (noise attenuation, thresholds, hold, etc.). Nothing hidden behind `.env` or query params. Offline-only denoisers appear in the same "Denoise chain" section, disabled with a "benchmark only" tag, so the panel is the single inventory of processing steps.

## Risks carried forward
- Realtime client DSP needs re-plumbing (mic → AudioContext → worklet → MediaStreamDestination → WebRTC track); interacts with the mic-mute-during-reply logic.
- Live-apply on Cascade means deliberate Deepgram reconnects; must not lose in-flight segments.
- Torch is heavy; "greyed out" state must be tested.
- Clean corpus can't show gains — all denoise claims come from noisy variants; clean baseline shown for regressions.
- `correct` mode can hurt; raw-vs-corrected WER per segment is the guard; `flag` is the safe default.
- RNNoise expects 48kHz/480-sample frames; no current context runs at 48k.
